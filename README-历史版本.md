# 中国象棋 AI v2.3（悬浮窗看门狗 · 无障碍服务加固 · 内置诊断日志）

一个从零手写的安卓中国象棋 App：**无广告、无加固、无第三方 SDK**。
纯 Java + 一个开源的皮卡鱼引擎二进制，任意 CPU 架构都能跑。

## 功能一览

### 三种模式（左上「模式」按钮切换）
| 模式 | 说明 |
|---|---|
| **对局** | 人机对弈，可选皮卡鱼 / 内置 AI，四档难度，悔棋、换边（自动翻转棋盘） |
| **分析** | 自由推演双方向走子，皮卡鱼 **3 路 MultiPV** 实时给分：着法 + 评分 + 搜索深度 |
| **摆谱** | 自定义局面：棋子调色板放子/删子、清空、回初始、选先手方、实时 FEN |

### 界面（v1.9 精简：省空间优先）
- 顶部只留**一行图标**（对局/分析/摆谱/扫图/悬浮窗）+ **一条分数条**（原状态文字行已删除）
- 底部 Tab 栏**默认收起**，点「分析/开局库/导航」才展开，再点收起；棋盘因此占满剩余空间

### 界面（白底暖色调，参考 Pro象棋）
- 暖白底 + 白色圆角卡片 + 暖褐文字 + 橙色强调，无深色背景
- **所有选项都在一级**：顶部工具条【对局｜分析｜摆谱｜扫图识谱｜悬浮窗识谱】，
  底部两行【新局｜悔棋｜换边｜难度】【导入FEN｜复制FEN｜初始局面｜关于】—— **没有任何二级菜单**
- 底部 **Tab【分析 / 开局库 / 导航】**，选中浅蓝底+蓝字高亮
- **分析 Tab**：表格展示 招法 / 胜率 / 分数 / 深度，最佳行高亮，棋盘蓝色箭头指出推荐走法
- **开局库 Tab**：24 条常见开局 + 自动匹配 + 库中推荐下一手
- **导航 Tab**：棋谱可点任意一手跳转复盘 + 起始/上一步/下一步/最新
- **走子动画**：棋子 300ms 缓出滑动到目标格（easeOutCubic）

### 引擎
**只保留皮卡鱼**（内置 AI 已移除，强度不足）。限深度出招（入门 d2 → 高级 d16 / 高级档限时 1.5s），
实测 7~50ms 出招；启动失败会明确报错而不是悄悄降级。

### 分析引擎（逐层加深，可与对弈共存）
- **逐层加深**：使用 `go infinite` 从 1 层开始不断加深（实测可到 d25+），深度变化即刷新表格，
  推荐着法会随深度变化而变化
- **与对弈共存**：分析用**独立的皮卡鱼进程**，与走子引擎互不干扰 —— 可以一边让 AI 走棋一边实时分析
- 「实时分析 开/关」按钮随时切换；分析结果自动跟随局面变化重新开始

### 扫图流程（v1.7）
> v1.8 修复：识别成功返回主界面时改成 NEW_TASK|CLEAR_TOP|SINGLE_TOP|REORDER_TO_FRONT，
> 避免被系统相册 Activity 卡在后台出现"白屏"；载入识别结果也加了异常保护。

点顶部「扫图」图标 → **直接打开系统相册**（自动申请照片权限）→ 选完图**立刻自动定位+自动识别**：
- 成功：直接载入摆谱模式，弹窗告知识别到多少子
- 失败：自动画出"它认为的棋盘网格"并提示手动点四个角（左上→右上→右下→左下），点「识别」即可
不再需要"选图片 / 自动检测 / 识别"三次点击。

### v2.3 修复你报的两个问题

**问题 A：悬浮小窗"点不动 / 会消失"**
根因：为了抓屏时不被自己挡住，我每轮把面板 `alpha=0`，一旦恢复那一步丢了，面板就永久隐身且点不到。
- 加**看门狗**：每 2.2 秒检查一次，面板透明超过 3 秒立即强制恢复（实测日志会打 `watchdog restore panel alpha`）
- 拖动条加宽加高，文字改为「≡ 实时识谱（按住这行拖动）」，好按
- 按钮从一行 5 个挤在一起 → **拆成两行**（轮到/立即识别/暂停 与 提示/自动走子），字号 13sp、内边距加大

**问题 B：小米开启无障碍提示"此服务出现故障"**
- 服务里所有系统调用全部 try/catch（绑定期抛异常正是系统提示"出现故障"的常见原因）
- 事件类型放宽为 `typeAllMask`，兼容国产 ROM 的绑定方式
- `dispatchGesture` 坐标做 NaN/负数保护，异常只记日志不外抛

**问题 C：真机上怎么把问题反馈给我**
点「关于」→ 现在会显示**诊断日志**（App 内直接看，不用 adb），截图发我即可；还能「清空日志」。
关键日志：`panel added` / `panel moved to x,y` / `watchdog restore panel alpha` / `autoplay branch: stable=?` / `tapTwice(...) = true|false` / `AutoService connected`
### v2.2 修复「点悬浮窗没反应」
原因：没有悬浮窗权限时，旧代码静默去跳系统设置页，而国产 ROM 上 `MANAGE_OVERLAY_PERMISSION` 常常解析不到，
`startActivity` 抛异常被吞掉 → 表现就是"点了完全没反应"。

现在：
- 无权限 → 弹出**明确对话框**「需要悬浮窗权限」+ 说明 + 「去设置」按钮（4 套意图兜底：
  MANAGE_OVERLAY_PERMISSION(package) → MANAGE_OVERLAY_PERMISSION → APPLICATION_DETAILS_SETTINGS → MANAGE_APPLICATIONS_SETTINGS）
- 有权限 → Toast「准备录屏授权…」→ 系统录屏弹窗 → 授权后 Toast「已开启：小棋盘会浮在屏幕左上…」
- 全链路打日志（`startFloatScan: overlay=? sdk=?`、`ShotActivity onCreate`、`AutoService connected`），出问题一看日志就知道卡在哪

悬浮窗完整使用前置：① 悬浮窗权限 ② 录屏授权 ③（要用自动走子才需要）无障碍服务

### 双引擎识谱（v2.0）
自动定位同时跑两条路，谁的结果更像一盘棋用谁：
1. **开源 RTMPose 角点模型**（`onnx/pose/4_v6-0301.onnx`，int8 量化 2.8MB）——对真实照片最稳
2. **自研投影网格**——对规整截图最稳
两条路的候选都会过一遍亚像素细化 + ±半格偏移搜索，再按"合法性 + 子数"取优。

**实测（用户提供的三张真图）**：
| 图 | 结果 |
|---|---|
| IMG_..._072805.jpg（天天象棋 桌面版照片，残局 10 子） | 自动识别 **10/10 全对** |
| IMG_..._072333.jpg（象棋2017 照片，中局） | 自动识别能出结果，但**裁剪错位时模型会给出"看着合法其实读错"的局面**，建议手动点四角 |
| Screenshot_..._com.tencent.q.jpg（天天象棋 手机截图） | 自动定位失败 → 引导手动点四角 |
| 斜拍照片 + **手动四角** | 实测 **0 错格**（testdata/full_pipe.py 可复现） |

> 结论：**手动点四角 + 开源模型 = 100% 可靠**；全自动在照片上仍不可靠，
> 因此界面在自动失败时会直接引导标定，并提供 3 倍放大镜。
### 自动定位与手动标定（v1.9）
- 自动定位：放宽长宽比约束（0.62~1.62 兼容透视）+ **四角坐标下降优化**
  （目标函数 = 交点处有墨、格心处无墨，四个角各自搜索，可纠正斜拍透视）
- **标定放大镜**：手动点角时长按拖动会显示 3 倍放大镜 + 十字准星，方便对准棋盘角
- 实测：**手工给四角坐标后，斜拍屏幕照片也能 0 错格识别**（PC 端验证，见 testdata 脚本）
- 结论：识别内核（校正 + 开源模型）是可靠的；**自动找棋盘**在强透视/低对比图源上仍有极限，
  此时点四角标定即可 100% 可靠
### 通用性修复（v1.8）
之前的定位算法在"棋盘和周围亮区被连通域并成一块"的图源上（如 Pro象棋 的木纹棋盘 + 下方白色面板）
会拟合出 **2 倍行距**，直接判失败。修复方式：
- **用列间距约束行间距**：象棋棋盘格子必须是正方形，先用列投影定出格宽，再据此约束行投影的搜索范围（保留 ±14% 容差以兼顾轻微透视）
- 配套：**线状暗像素投影**（压制木质棋子圆盘的干扰）、**畸变闸门**、**亚像素细化**、**多候选对齐**

回归测试（testdata/ 内有样本与生成脚本）：
| 测试图 | 结果 |
|---|---|
| 本 App 截图 | grid 112x113 → 32/32 通过 |
| Pro象棋 风格木纹棋盘（合成） | grid 114x114 → 32/32 通过 |
| 上述 + 状态栏/图标栏/绿箭头/蓝选框干扰 | grid 114x114 → 32/32 通过 |
| 棋盘带表格干扰的旧截图 | 老实报 grid rejected（不再输出垃圾） |

### 识别可靠性（v1.7）
- **畸变闸门**：定位出的网格格子必须接近正方（0.86~1.16），否则判定失败 —— 专门治"把表格/文字区当成棋盘"而输出满盘车炮
- **亚像素对齐细化**：让交点处墨迹最多、格心最少，把网格锁死在交叉点上
- **多候选对齐**：再试 ±半格偏移的网格，用模型置信度挑最好的那个
- **结果合法性校验**：车马炮数量超限 / 双方无子 / 总数异常 → 拒绝，绝不输出垃圾局面
- 实测：标准棋盘截图 32/32 全对，约 1.2 秒；干扰图老实报"没认到棋盘"并引导手动标定

### 扫谱识局（接入开源深度学习识别）
- **识别模型**：开源项目 [TheOne1006/chinese-chess-recognition](https://github.com/TheOne1006/chinese-chess-recognition)
  的棋局分类模型（Swin-Transformer v2 nano，输入 280x315 校正棋盘，输出 10x9x16 分类）
- **推理运行时**：ONNX Runtime for Android（Microsoft，开源，Maven Central）
- 模型经 **int8 动态量化**：31.1MB → **9.6MB**，精度零损失（PC 端实测 0 错格）
- 流程：自研几何定位（投影网格拟合）→ 半格外扩校正 → 归一化 → 模型 → 每格 argmax
- **定位质量关**：网格不接近正方形直接判定失败并提示手动标定四角，绝不再输出垃圾局面
- **结果合法性校验**：车马炮数量超限 / 双方无子 / 总数异常 → 拒绝并提示校正

## 构建（无需 Android Studio / Gradle）
一键脚本 `D:\dsh\apkwork\build-xiangqi.mjs`：
aapt2 编资源 → ecj 编译 Java → d8 转 dex → 打包（resources.arsc 必须 STORE）
→ zipalign 对齐 → apksig 签名（v1+v2+v3）。

引擎与权重：
- `jniLibs/arm64-v8a/libpikafish.so` ← 官方 `Pikafish-Android-arm64-universal`
- `jniLibs/x86_64/libpikafish.so` ← 本机用 NDK r30 从源码编译（`make ARCH=x86-64 COMP=ndk`）
- `assets/pikafish.nnue` ← 官方权重（50.7MB），首次运行释放到私有目录并交给 UCI `EvalFile`

## 已知限制
- 皮卡鱼二进制以 API 29 为目标，**需 Android 10+**；低版本自动回退内置 AI
- 识别针对"线描式棋谱图"（截图、电子书、印刷图）；实拍照片请手动点四角校准，识别后可在摆谱模式一键修正
- 未实现长将/长捉循环裁决；无云库
